# Feature 27.1 — Stats section in the profile

**Feature ID:** `me-stats` (from `feature_list.json`)

**Status:** in progress

---

## What we built

The `/profile` page now shows a live **Stats** section: the authenticated
user's aggregate record (games played, wins, losses, draws) and a win rate,
read once from `GET /api/me/stats` on mount. It mirrors the existing
`FriendsSection` discipline — an announced spinner while loading, a quiet
"No games yet." empty state when the user has zero games, and a graceful
error fallback line if the fetch fails. It replaces the former "Stats"
placeholder Paper; "My games" stays a placeholder (game-reviews is next).

## TS / React concepts that appear

- **Boundary narrowing of an all-optional generated type** — `openapi-typescript`
  types every field of `MyStatsResponse` as optional (Spring's `@Schema`
  doesn't mark them `required`). `narrowMyStats` in `src/api/me.ts` is a
  total function `GeneratedMyStats | undefined → MyStats` that throws
  `ApiError(UNKNOWN_ERROR)` if any required field is missing, so the rest of
  the app consumes a `Readonly<{...}>` with all six fields guaranteed
  present. Same pattern as `narrowMeResponse` / `narrowFriend`.
- **`useEffect` with a `cancelled` flag** — the one-shot fetch flips state in
  `.then`/`.catch`/`.finally`. We never call `setState` synchronously in the
  effect body (it would trip `react-hooks/set-state-in-effect` and cascade a
  render), only after the promise settles. The cleanup sets `cancelled = true`
  so a late resolution after unmount is a no-op — the React equivalent of
  cancelling a fiber on scope exit.
- **Discriminated render via a small state machine** — `loading` / `errored` /
  `stats === null || total === 0` / loaded are rendered as a nested ternary
  ladder. The empty and the "still null" cases collapse into one branch so a
  null result can never reach the loaded view.
- **`Readonly<T>` on the DTO** — `MyStats` is a `Readonly<{...}>`; the API
  layer owns the only construction site (the narrower), and downstream code
  cannot mutate it. Compile-time only — it does not freeze the object at
  runtime.

## Decisions taken

- **Decision:** put the wrapper in a **new `src/api/me.ts`** module rather than
  extend `auth.ts`.
  - **Alternatives considered:** add `getMyStats` to `auth.ts` (which already
    holds `me()`); or to a generic `profile.ts`.
  - **Why this one:** `auth.ts` is the _auth_ surface (login / register / me).
    `/api/me/stats` is the start of the non-auth `/api/me/*` surface; the next
    two features (edit-profile: `PATCH /api/me`, `PUT /api/me/password`) belong
    here too, so `me.ts` gives them a stable home and keeps `auth.ts` focused.

- **Decision:** treat `winRate` as a **fraction in [0, 1]** and format it as a
  whole-number percentage in the UI (`0.5 → "50%"`).
  - **Alternatives considered:** assume it is already a percent (0–100) and
    render it verbatim.
  - **Why this one:** this is **verified, not assumed.** The backend computes
    `double winRate = decided == 0L ? 0.0 : (double) view.wins() / decided;`
    in `chess-backend-java/.../web/me/MyStatsResponse.java` (decided = wins +
    losses + draws). The OpenAPI schema agrees: `@example 0.5`, "Win rate over
    decided games … 0.0 when there are no decided games." So it is a fraction;
    `formatWinRate` multiplies by 100 and rounds. (No live prod GET was made —
    the source-of-truth backend code settled it.)

- **Decision:** show `unknown` only when `> 0`, as a discreet caption, and tell
  the user it is excluded from the win rate.
  - **Alternatives considered:** always show an "unknown" stat tile; or hide it
    entirely.
  - **Why this one:** `unknown` is a legacy data artifact (old ABANDONED rows
    with an unrecoverable winner). For most users it is 0 and would be noise as
    a permanent tile; when non-zero it explains why `wins + losses + draws`
    doesn't equal `total`, which is worth a one-line footnote.

- **Decision:** render the win rate as **text** (`Win rate: 50%`) and each count
  as a number + label, never colour-only — satisfies the a11y requirement that
  state isn't conveyed by colour alone.

## How this compares to what I know

- **In http4s + circe this would be...** `getMyStats` is the equivalent of a
  `Client[IO]`-driven `client.expect[MyStats](req)` where `MyStats` is a case
  class with a derived circe `Decoder`. The crucial difference: circe's
  `Decoder` _fails the decode_ when a required field is absent (a `DecodingFailure`
  in the `F`), whereas here the generated TS type makes every field optional and
  the decode "succeeds" with `undefined` holes. `narrowMyStats` is the
  hand-written `Decoder` that restores the "all-or-nothing" guarantee circe
  would give you for free — it's the boundary where we re-introduce totality.
- **In Cats Effect this would be...** the `useEffect` + `cancelled` flag is a
  poor-man's `Resource`/fiber cancellation. In CE you'd `fiber.cancel()` on
  scope exit; here the effect's cleanup closure sets a boolean the async
  callbacks check before touching state. Same intent (don't complete an effect
  whose scope is gone), far less guarantee — a `setState` after unmount is
  merely ignored, not structurally prevented.
- **Error channel:** `ApiError` thrown out of the wrapper is this codebase's
  `EitherT`/`MonadError` analogue — a typed failure the React layer catches and
  maps to copy, instead of pattern-matching a sealed `ErrorResponse` ADT in a
  `flatMap`.

## Gotchas / things I learned the hard way

- The `winRate` format was the one real risk the plan flagged. Reading the
  backend (`MyStatsResponse.java`) rather than guessing was decisive and quick —
  the division `(double) wins / decided` is unambiguously a fraction.
- The Profile test didn't register a `/api/me/stats` handler, so adding the
  live section would have made MSW log an unhandled request and the section
  would hit its error fallback. Added a quiet default stats handler to the
  test's mount-time handlers (the same approach already used there for the four
  FriendsSection requests).
