# Feature 20.2 — Auth plumbing (api/auth client, token storage, Authorization middleware, UserContext authed arm + logout)

**Feature ID:** `auth-core` (from `feature_list.json`)

**Status:** done

---

## What we built

The non-UI half of user accounts: a typed `src/api/auth.ts` client
(`login` / `register` / `me`), JWT persistence in `localStorage`, a
central openapi-fetch middleware that injects `Authorization: Bearer
<token>` on every request when a token is present, and the `UserContext`
seams that turn an `AuthSession` into the `Authenticated` identity arm
(`setAuthenticated`), tear it down (`logout`), and rehydrate it on app
load from a stored token. No login/register pages, no Header wiring, no
Google/callback route — those are sub-features 20.3 and 20.4. This slice
makes a signed-in identity _possible_; the UI that drives it lands next.

## TS / React concepts that appear

- **openapi-fetch middleware (`client.use({ onRequest })`)** — the
  library exposes an interceptor chain. `onRequest({ request })` receives
  the live `Request` whose `headers` is a mutable `Headers` instance; we
  `request.headers.set('Authorization', …)` in place and return nothing.
  Returning `void` keeps the same request object. Reading the token
  _inside_ `onRequest` (not at client-construction time) means a
  login/logout that mutates `localStorage` takes effect on the very next
  call without rebuilding the client. See `src/api/client.ts`.

- **Boundary narrowing (optional generated fields → mandatory app
  type)** — openapi-typescript marks every `MeResponse` / `AuthResponse`
  field optional because Spring's `@Schema` does not declare them
  `required`. `narrowMeResponse` / `narrowAuthResponse` collapse the
  `T | undefined` fields into a `Readonly<{…}>` with no optionals, or
  throw `ApiError(UNKNOWN_ERROR)` on an incomplete payload — mirroring
  `narrowRoomResponse` in `rooms.ts`. The wire field `id` is renamed to
  `userId` here so the type matches `AuthenticatedIdentity.userId`.

- **`useEffect` with a `cancelled` flag** — the rehydration effect kicks
  off an async `me()` and must not call `setIdentityState` after the
  Provider unmounts (StrictMode double-invokes effects in dev; a fast
  route change could unmount before the fetch resolves). The cleanup
  function flips `cancelled = true`; the `.then` checks it before
  setting state. The dep list is intentionally empty (mount-only) with
  an `eslint-disable-next-line` documenting why re-running on identity
  changes would be wrong (it would re-fetch `me()` after every login).

- **Discriminated-union identity (`IdentityKind.Guest |
.Authenticated`)** — `setAuthenticated` and the rehydration success
  path construct the `Authenticated` arm; `logout` resets to the guest
  default. TypeScript narrows `userId` onto the authenticated branch
  only, so a consumer that reads `identity.userId` must first check
  `identity.kind === IdentityKind.Authenticated`.

- **Co-located Vitest + MSW tests** — the auth wrappers are tested
  against MSW handlers registered on `TEST_API_BASE_URL`, exercising the
  real `fetch` + middleware path rather than a stubbed function. The
  UserContext rehydration tests register a `/api/me` handler and
  `waitFor` the async identity flip.

## Decisions taken

- **`wrapNetwork` extracted from `rooms.ts` into `src/api/http.ts`.**
  - _Decision:_ move the network-error translation helper into a shared
    module both `rooms.ts` and `auth.ts` import.
  - _Alternatives:_ duplicate the function in `auth.ts`; or re-export it
    from `rooms.ts` (making `auth` depend on `rooms`).
  - _Why this one:_ one implementation, no cross-coupling of the two
    domain modules, and `rooms.ts` behaviour stays byte-identical (its
    tests are unchanged and still pass). `http.ts` is the natural home
    for future transport-layer helpers.

- **`localStorage`, not `sessionStorage`, for the JWT.**
  - _Decision:_ persist the token under `chess-room.authToken` in
    `localStorage`.
  - _Alternatives:_ `sessionStorage` (tab-scoped); in-memory only.
  - _Why this one:_ the backend issues a 7-day JWT with no refresh
    endpoint. The credential is meant to outlive a tab — reopening the
    app the next day should keep the user signed in. This is the
    mirror-image of `sessionStorage.ts`, which deliberately holds the
    tab-scoped _room_ session (closing the tab ends the game). The key
    is namespaced `chess-room.*` to match the other localStorage keys.

- **Middleware applied to BOTH `apiClient` and `createApiClient`.**
  - _Decision:_ a `withAuth(client)` helper wraps the production
    singleton and the test hatch alike.
  - _Alternatives:_ apply it only to `apiClient` and let tests bypass
    the header path.
  - _Why this one:_ MSW tests then exercise the real injection path. The
    `client.test.ts` middleware assertions (token present → `Bearer …`;
    no token → header absent; fresh read per request) would be
    meaningless against a client that does not carry the middleware.

- **`logout()` calls `leaveRoom()`; the confirm dialog is deferred to
  20.3.**
  - _Decision:_ the pure primitive clears token + identity + room (and
    the persisted room session via `leaveRoom`).
  - _Alternatives:_ gate `logout` behind a confirmation here.
  - _Why this one:_ logout applies only to a registered user; an
    anonymous user has no session to close. A registered user who logs
    out mid-game is ejected. But the "you have a game in progress —
    logging out abandons it" warning is UI, and the Logout button lives
    in the Header, which 20.3 builds. 20.3 gates the `logout()` call
    behind a confirm when `room.phase === RoomPhase.InRoom`. `auth-core`
    ships the side-effect-free primitive only.

- **Rehydration distinguishes 401 from a network blip.**
  - _Decision:_ on mount, if a token exists and no explicit
    `initialIdentity` was passed, call `me()`. Success → authenticated.
    Failure where `code === AUTHENTICATION_REQUIRED || httpStatus ===
401` → `clearToken()` + stay guest. Any other failure (network) →
    _keep_ the token + stay guest.
  - _Alternatives:_ clear the token on any failure.
  - _Why this one:_ a stale/expired token should not survive (otherwise
    every load retries a dead credential), but a transient transport
    failure should not silently sign the user out of a possibly-valid
    session. The brief guest→authenticated flip is acceptable because no
    auth UI ships here (the Header that would flash is 20.3).

- **`setAuthenticated` takes the full `AuthSession`, no extra `me()`.**
  - The login/register/OAuth flows already hold the user in the
    `AuthResponse`, so `setAuthenticated(session)` lifts `session.user`
    straight into the identity. Only the _rehydration_ path (token but
    no user in hand) pays the `me()` round-trip.

## How this compares to what I know

- **The Authorization middleware is `Kleisli`-style request
  transformation.** In http4s you would write a `Client[F] =>
Client[F]` middleware (e.g. `Client.translate` / a `Kleisli[F,
Request, Response]` wrapper) that adds the `Authorization` header
  before delegating. `withAuth(client)` is exactly that shape: a
  `Client<paths> => Client<paths>` that registers an `onRequest` hook.
  The difference is mutation — openapi-fetch hands you a mutable
  `Headers` to poke, where http4s would have you build a new immutable
  `Request` with `.putHeaders(…)`.

- **`narrowAuthResponse` is `circe.Decoder` collapsed to `Option`.** The
  generated type is the loose "everything optional" shape Jackson would
  emit without `@JsonProperty(required = true)`. The narrow function is
  the `Decoder[AuthSession]` at the entity boundary — except instead of
  `Either[DecodingFailure, A]` we throw a typed `ApiError(UNKNOWN_ERROR)`,
  because every caller's recovery is identical ("the server sent
  garbage; show the generic error").

- **`useEffect` rehydration vs `Resource`.** The mount effect is an
  acquire-with-release: the `me()` fetch is the acquire, the `cancelled`
  flag is the release guarding against use-after-unmount. In Cats Effect
  the same shape is `Resource.make(fetchMe)(_ => IO.unit)` run for its
  effect, with cancellation handled by the fiber being cancelled on
  scope exit. React makes you write the cancellation guard by hand
  because effects are fire-and-forget, not cancellable fibers.

- **Discriminated-union identity = a sealed trait.** `Identity =
GuestIdentity | AuthenticatedIdentity` is `sealed trait Identity` with
  two case classes; the `kind` field is the discriminator a `match` (or
  `if`) narrows on. TypeScript's exhaustiveness is weaker than Scala's
  (no compiler-forced `match` completeness without the `never` trick),
  but the narrowing on `kind` is the same ergonomics.

## Gotchas / things I learned the hard way

- A `vi.spyOn(window, 'localStorage', 'get')` that throws will also make
  the test's own `afterEach` cleanup `window.localStorage.clear()` throw
  — `vi.restoreAllMocks()` must run _before_ the `clear()` in teardown,
  not after.
- The rehydration tests rely on the production `apiClient` pointing at
  `http://localhost:8080`, which is the same origin as
  `TEST_API_BASE_URL`, so MSW handlers registered in the test intercept
  the effect's `me()` call without any client injection. The
  vitest setup runs `onUnhandledRequest: 'error'`, which is what makes
  the "no token → no `me()` call" test meaningful: an accidental fetch
  would fail loudly.
- `ApiErrorCode` was already imported in `rooms.ts` for `narrowRole`, so
  removing the local `wrapNetwork` (the only other consumer of
  `ApiErrorCode` in that file via the `NetworkError` path) did not leave
  an unused import — the named import stays valid.
